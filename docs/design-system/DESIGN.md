# DESIGN.md

## 1. Visual Direction

Style: Wise-inspired professional financial SaaS: bright, plain-spoken, trustworthy, and operationally clear.

The UI should feel like a real Broker SaaS / financial operation platform with a Wise-inspired visual language: white surfaces, green-tinted neutrals, forest-green text, bright-green primary actions, rounded controls, and clear money/status information. Do not use Wise logos or brand marks.

## 2. Design Principles

| Principle | Rule |
|---|---|
| Clarity first | Users must understand current status and next action within 3 seconds. |
| Trustworthy | Use calm colors, stable layout, clear financial information. |
| Friendly precision | Keep copy plain and human while preserving compliance accuracy. |
| Data readability | Amounts, accounts, statuses, timestamps must be easy to scan. |
| Compliance visibility | Risk, review, failed, and blocked states must be explicit. |
| Reusable system | Do not create one-off UI styles. |
| Low decoration | Do not use decoration unless it supports comprehension. |

## 3. Visual Style Rules

### Recommended

- White or light green-neutral surfaces.
- Clear border and spacing.
- Subtle shadows only for important containers.
- High contrast typography.
- Forest green text, bright green primary actions, and restrained semantic status colors.
- Compact but readable density.
- Use status colors only to clarify meaning, never as decoration.
- Rounded pills for primary actions and status indicators.

### Avoid

- Random gradients.
- Heavy glassmorphism.
- Excessive blur.
- Overly playful illustrations.
- Too many primary buttons.
- Colorful dashboards without information purpose.
- Unexplained icon decoration.
- Wise logos, brand marks, or exact marketing assets unless provided by the user.

## 4. Page Structure

Every page should follow this structure when applicable:

1. Page header.
2. Current status / key summary.
3. Main content area.
4. Primary action area.
5. Secondary operation area.
6. Risk / compliance / helper message.
7. State feedback area.

## 5. Financial Product Tone

Use copy that is direct, specific, and operational. Risk and compliance messages should say what happened, why it matters, and what the user can do next. Avoid vague copy such as "Something went wrong" when money movement, account access, or review status is involved.
