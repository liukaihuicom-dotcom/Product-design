# 14-ACCESSIBILITY.md

## Accessibility Goal

Make Web/App prototypes readable, operable, and understandable.

## Core Rules

| Area | Rule |
|---|---|
| Color | Do not rely on color alone |
| Contrast | Text must be readable |
| Icon | Important icons need labels or visible paired text |
| Button | Icon-only buttons need aria-label |
| Form | Inputs need labels and error messages |
| Focus | Web controls need visible focus state |
| Keyboard | Web modal and forms should support keyboard navigation |
| Status | Status must include text |
| Motion | Avoid excessive motion |

## Financial Product Accessibility

- Risk and compliance messages must be text-based.
- Amount and currency must be readable.
- Failed states must explain recovery action.
- Disabled actions must explain why unavailable.
